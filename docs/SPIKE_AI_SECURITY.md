# SPIKE OS — GEMINI AI ASSISTANT SECURITY & PRIVACY

## 1. API Key & Credential Protection

- **Server-Side Isolation**: The Gemini API key (`Gemini:ApiKey` / `GEMINI_API_KEY`) is read exclusively on the server inside `GeminiClient` (`Services/GeminiAssistantService.cs`) and transmitted via the `x-goog-api-key` HTTP header over HTTPS to `https://generativelanguage.googleapis.com/v1beta`.
- **Zero Client Exposure**: The API key is never rendered into Razor views, never returned by `/api/assistant/status`, and never referenced in `wwwroot/js/mascot-assistant.js`.
- **Zero Git / Source Exposure**: `appsettings.json` stores `"ApiKey": ""`. Development credentials live in `.NET User Secrets` (`UserSecretsId: f3577ece-adbf-45e5-8ad3-e32c14fcc3a2`) or the `GEMINI_API_KEY` environment variable.
- **Safe Logging**: `GeminiClient` logs only HTTP status codes, model names, and exception types—never request headers, raw API keys, or sensitive payloads.

---

## 2. Read-Only Tool Allowlist & Zero-Mutation Guarantee

`SpikeAssistantToolService.ExecuteToolAsync` enforces a strict static allowlist (`AllowedToolNames`):

1. `get_club_info`
2. `check_court_availability`
3. `get_pricing_quote`
4. `search_proshop_products`
5. `get_website_guide`
6. `get_my_bookings`

- Any tool call outside this allowlist is immediately rejected (`IsToolAllowlisted(toolName) == false`) and returns `{ ok = false, error = "Tool is not permitted." }` with a warning log.
- All EF Core queries in `SpikeAssistantToolService` use `.AsNoTracking()` and read-only projections. The assistant cannot execute arbitrary SQL, create/modify/cancel bookings, alter prices, or modify accounts.

---

## 3. Personal Data & Cross-Account Isolation (`get_my_bookings`)

Personal booking queries are protected by three mandatory rules in `SpikeAssistantToolService.GetMyBookingsAsync`:

1. **Authenticated Member Isolation**: When `actor.IsAuthenticated && actor.AccountId > 0`, the EF Core query filters strictly by `Where(b => b.AccountId == actor.AccountId)`. Even if a logged-in user prompts the assistant with another customer's `BookingCode`, the query returns `found = false` and zero details of the other customer's booking.
2. **Guest Token Verification**: For unauthenticated guests, `get_my_bookings` only returns a booking if both `bookingCode` and `guestAccessToken` are supplied AND `QrTokenService.VerifyGuestAccessToken(actor.GuestAccessToken, booking.AccessTokenHash)` succeeds.
3. **Unauthenticated Fallback**: Anonymous callers without a verified token receive `authorized = false`, `requiresAuthenticationOrLookup = true`, and safe links to `/Account/Login` and `/Lookup`.

## 4. Session Memory Isolation

- Multi-turn conversation history in `IMemoryCache` is keyed by `spk_ai_conv:{sessionPartitionKey}:{cleanConvId}`.
- `AssistantController.ResolveSessionPartitionKey` partitions sessions by:
  - `acc:{AccountId}` for authenticated users.
  - `guest:{spike_ai_sid}` for unauthenticated guests, where `spike_ai_sid` is an `HttpOnly`, `SameSite=Lax` cookie generated by the server.
- Because `sessionPartitionKey` is derived from server-verified session/cookie state rather than client-supplied JSON, a guest or another user cannot read or hijack another user's conversation history even if they send the same `conversationId`.

---

## 5. Prompt Injection, Abuse & Cost Controls

- **Untrusted Input & Output Sanitization**:
  - User messages are stripped of control characters and capped at `MaxInputChars` (`500` chars default; requests exceeding `500` chars are rejected with HTTP `400 MESSAGE_TOO_LONG` before calling Gemini).
  - Database fields returned by tools are sanitized via `SpikeAssistantToolService.SanitizeUntrustedText` (strips HTML tags and control characters) to mitigate indirect prompt injection.
  - Assistant responses are rendered in the browser via `textContent` / escaped text nodes (`renderFormattedReply` in `wwwroot/js/mascot-assistant.js` never injects raw HTML from the model) and only allowlisted internal routes (`/`, `/Booking`, `/Product`, `/Lookup`, `/Account/Profile`, `/Account/Login`) are rendered as action pills.
- **CSRF & Rate Limiting**:
  - `POST /api/assistant/chat` and `POST /api/assistant/reset` enforce `[ValidateAntiForgeryToken]` and `[EnableRateLimiting("AssistantLimiter")]` (default `15` requests/minute per IP).
- **Concurrency & Duplicate Submission Guards**:
  - `GeminiAssistantService` bounds concurrent upstream Gemini calls with a `SemaphoreSlim(6, 6)` and blocks identical in-flight duplicate submissions from the same session via `InFlightFingerprints`.
